# Onshape arm source and joint review

**For the complete current robot, download [cad/assembly.step](../assembly.step).** This source assembly predates the generated C3 electronics enclosure.

The user's last Onshape export is the arm design source. The exploratory [MuJoCo model](../../sim/onshape/README.md) is now generated from this import. Earlier concept versions remain in Git history. Current hardware calibration and controller limits are documented with the [current simulation](../../sim/README.md).

Slicer-derived printed masses and preliminary CAD-based inertia are recorded in [sim/mass_properties](../../sim/mass_properties/README.md). The MuJoCo builder combines those records with explicit hardware mass/distribution assumptions; the full physical mass model is still unmeasured.

## Current status

The latest whole-assembly export, [source/robot_onshape_third.step](source/robot_onshape_third.step), is the current generator input. Superseded exports have been removed; their history remains in Git. It contains nine placed instances. The same-named servo instances have distinct placements, so they are assigned lower_servo and upper_servo aliases by their vertical positions. Original names are retained in assembly_inspection.json.

**Third export reviewed:** only the upper servo moved, by -0.15 mm in Z relative to the second export; the other eight placements are unchanged. The remaining shaft discrepancy is +0.55 mm in X and +0.15 mm in Z (0.570088 mm perpendicular to the axis). A further translation (-0.55, 0, -0.15) mm in exported assembly coordinates would align that servo model. The user confirms the structural upper pivot is correct. Keep that pivot as the kinematic reference; no imported geometry has been silently aligned. Whether the residual difference comes from the component model or assembly placement is not established.

Eight component BReps pass the OpenCascade validity check; the detailed controller model does not. It meshes for visual review, but should use simplified collision geometry and measured/estimated mass rather than treating its detailed solid as authoritative.

## Review artifacts

- review.html: self-contained 3D orbit viewer, group visibility and two virtual hinge sliders. The sliders are visual previews, not validated physical travel limits or collision checks.
- review.png: two-view geometry preview and upper-axis comparison, generated by render_review.py.
- geometry.json: placed triangle meshes and candidate axes.
- joint_map.json: proposed chain, structural origins and axes, with uncalibrated fields explicit.
- assembly_inspection.json: component names, aliases, placements, bounding boxes and cylindrical surfaces.

Reproduce using the existing .venv-cad Python environment:

```sh
.venv-cad/bin/python cad/onshape_import/import_assembly.py
.venv-cad/bin/python cad/onshape_import/build_review.py
.venv-cad/bin/python cad/onshape_import/render_review.py
```

The geometry-only importer uses OpenCascade directly; it does not import the full CadQuery visualization stack. Browser inspection confirmed WebGL rendering without console errors and independently moving lower/upper previews. No robot motion or training commands were sent during this CAD review.
